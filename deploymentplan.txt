0. GROUND RULES
--------------------------------------------------------------------------------

NOTHING RUNS ON YOUR LAPTOP.

  Cloudflare Pages  serves the frontend        (static HTML + wasm)
  Fly.io            runs the Go binary         (url-shortener-go)
  Neon              holds the Postgres data    (2 shards)

Once this is done your machine can be closed forever. It is only involved for
`git push`. Nothing is ever served from localhost.

Local tooling status (checked): gh, flyctl, docker, psql, node, npm and go are
all MISSING. cargo is present. Consequences:

  - You cannot rebuild the wasm locally (no Go). This does not matter:
    frontend/static/*.wasm is already committed and pushed. It is exactly why
    we can skip the Cloudflare build step entirely.
  - You only need Go installed if you later change chapters 1.4 / 1.5 / 1.7
    and want to regenerate machine.wasm via frontend/build.sh.
  - Fly is the only phase needing a CLI install. Fly builds remotely, so you
    do NOT need Docker.

Git state (checked): main is in sync with origin/main. GitHub already has
everything Cloudflare needs.


--------------------------------------------------------------------------------
1. WHY THIS IS CHEAP — THREE FINDINGS FROM THE CODE
--------------------------------------------------------------------------------

(1) NO BUILD STEP NEEDED.
    frontend/static/ is already committed: machine.wasm, wasm_exec.js,
    machine_rs_bg.wasm, machine_rs.js, corpus.tsv. Set the Pages build command
    to EMPTY and the output directory to `frontend`. This removes the entire
    Go + Rust + submodule build-environment problem, the GO_VERSION variable,
    and the wasm-bindgen version-pinning hazard.

(2) REDIS IS OPTIONAL — DROP IT.
    cmd/server/main.go:47 only WARNS when Redis is unreachable. NewRedisStore
    is constructed with the in-memory store as its fallback, and
    rate-limiter-go/store/redis.go:101 routes every Redis error to it. On a
    single instance, in-memory rate limiting is the correct choice anyway.

(3) GEOIP IS OPTIONAL — DROP IT.
    internal/geoip/geoip.go returns a no-op resolver when the .mmdb file is
    missing. Skip the MaxMind account entirely.

That leaves POSTGRES as the only hard dependency.
internal/config/config.go:53 fails without DB_SHARD_0_DSN.


--------------------------------------------------------------------------------
2. WHY A CUSTOM DOMAIN IS FUNCTIONAL, NOT COSMETIC
--------------------------------------------------------------------------------

frontend/index.html:1052 renders j.short_url at 26px and computes a
"% smaller" stat from its length. That string is built at
internal/handler/links.go:111 from BASE_URL.

On a raw hostname like url-shortener-zeayush.fly.dev the "shortened" URL is
~44 characters, so the panel's headline number would be feeble or negative.
A short domain is what makes the 1.8 demo land.

PICK A SHORT DOMAIN. Every character is subtracted from that stat.

4. ARCHITECTURE — ONE DOMAIN, TWO HOSTNAMES
--------------------------------------------------------------------------------

  yourdomain.com     -> Cloudflare Pages   (the Machine Room)
  s.yourdomain.com   -> Fly                (redirects + BASE_URL)

The second hostname is REQUIRED, not optional. The shortener's redirect route
is `GET /:code` at the root, which would collide with the static site if you
tried to serve both from one hostname.

Browser -> Pages (static wasm panels 1.4/1.5/1.7/1.13, all client-side)
        -> Pages Function /api/* -> Fly -> Neon   (panel 1.8)
        -> s.yourdomain.com/:code -> Fly -> Neon  (actual redirects)

"shard-1" matching the slice index; reordering them remaps every key.

PHASE E — CONNECT THEM                             ~10 min    $0
================================================================================

[ ] E1. fly certs add s.yourdomain.com

[ ] E2. In Cloudflare DNS for your domain add a CNAME:
            Name:    s
            Target:  <app>.fly.dev
            Proxy:   DNS ONLY  (GREY CLOUD, PROXY OFF)

        Fly's certificate challenge FAILS behind Cloudflare's proxy. Leave it
        grey permanently — a redirect endpoint gains nothing from proxying.

[ ] E3. Wait for `fly certs show s.yourdomain.com` to report the cert issued
        (usually under a minute).

[ ] E4. Pages project -> Settings -> Environment variables, add:

            SHORTENER_ORIGIN = https://<app>.fly.dev

        Use the fly.dev hostname here, NOT your subdomain. That keeps the
        origin-hiding property the proxy in
        frontend/functions/api/[[path]].js is built around.

[ ] E5. *** TELL CLAUDE WHEN E4 IS DONE. ***
        Claude then:
          - flips SHORTENER_API to "/api" at frontend/index.html:472

THE FLIP IS DELIBERATELY LAST. Setting SHORTENER_API earlier replaces the
panel's clean "not deployed" message with connection errors.


================================================================================
5. WHAT TO EXPECT ONCE RUNNING
================================================================================

After ~5 minutes of no traffic Neon suspends and the Fly machine stops. The
next visitor wakes both.

KNOWN EDGE CASE: internal/repository/postgres.go:32 pings with a 5-second
timeout and calls os.Exit(1) on failure. A cold container hitting a cold
database can therefore crash once. Fly restarts it automatically and the retry
succeeds against a now-awake Neon. The /health warm-up added in E5 fires this
on page load, so a visitor never sees it.

That is the price of $0 compute. If it ever annoys you, setting Fly's
min_machines_running = 1 makes it disappear for ~$2/mo.

DO NOT stack scale-to-zero on both tiers without the warm-up.
